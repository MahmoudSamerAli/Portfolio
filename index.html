Featured Project Web / Backend

InfoLink

Internal information search platform with role-based access, JWT auth, and MongoDB/SQL Server hybrid storage

InfoLink is a production-ready Spring Boot 4.1 (Java 26) REST API that serves as an organizational search platform. Authenticated users search records across group-scoped MongoDB collections, while administrators manage users, groups, and collection access mappings. Every search is logged for auditing. The backend also serves the frontend as static resources — a fully self-contained deployment.

Java 26 Spring Boot 4.1 MongoDB SQL Server JWT Auth Spring Security Maven Swagger/OpenAPI
JWT + Refresh Rotation
Role-Based Access (USER/ADMIN/SYSADMIN)
Group-Scoped MongoDB Search
Full Audit Logging
View Source Code

API Endpoints

Auth
  • POST /auth/login — Returns access + refresh tokens
  • POST /auth/refresh — Rotates refresh token (single-use)
  • POST /auth/logout — Revokes refresh token server-side
Users & Groups
  • GET/POST/PATCH/DELETE /users/** — Admin user management
  • GET/POST/PUT/DELETE /group/** — Admin group management
  • GET /users/profile — Current user profile
Collections & Search
  • GET /api/collections?groupId= — Accessible collections
  • POST /api/collections — Create collection (+ optional grant)
  • POST /api/collections/{name}/upload — CSV/JSON upload
  • GET /api/search — Group-scoped regex search (logged)
  • POST /api/search/deep — Admin cross-collection search
Logs
  • GET /logs — Admin: all logs (paginated, searchable)
  • GET /logs/me — User: own history + counters

Data Model

User

username, BCrypt password, fullName, role (USER/ADMIN/SYSADMIN), group, active, createdAt

Groups

name, description, active

GroupsCollections

Maps group → allowed MongoDB collection names

Log

user, collection, keyword, timestamp, IP, hit/miss

Key Technical Highlights

  • Refresh token rotation: Single-use, 30-min expiry, shared in-flight refresh prevents race conditions
  • Group-scoped search: Users only search collections their group has been granted access to
  • Hybrid storage: SQL Server (users, groups, logs) + MongoDB (searchable document collections)
  • Validation & error handling: Jakarta Bean Validation + global exception handler with consistent error shapes
  • Frontend: Vanilla JS SPA served as static resources, token management via data-store.js (auto-refresh on 401)
  • File upload: CSV/JSON streaming into MongoDB (append-only), zip-slip-safe Excel converter implemented but not yet wired
